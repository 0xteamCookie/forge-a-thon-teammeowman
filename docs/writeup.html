2. Starting point

From scratch. No upstream fork. We read Continue, Cline, Roo Code and opencode first. Roo Code was archived in May 2026 and opencode is a terminal app. In Continue and Cline the diff view and the task loop are tied into their own model layer, telemetry and webview protocol, so a fork would mostly have meant deleting code. We wanted a small codebase in which every part is about what this track scores: what the model sees, and a safe editor. For the diff we reuse VS Code's own diff editor rather than writing a renderer. Runtime dependencies: @truefoundry/trueforge-sdk, @modelcontextprotocol/sdk, diff.

3. Architecture on TrueForge

Figure 1. The extension is a TrueForge client. It opens sessions and sends turns through the SDK and renders the streamed events. Everything the agent can do in the editor is an MCP tool, so the agent, not the extension, decides what to read and change.
  • Approval drives the review. The agent definition sets require_approval_for_tools on the three write tools. When TrueForge pauses on one, Anvil applies the proposed edit in memory and opens it in the diff editor with Accept / Reject on every hunk (Fig. 3). Nothing touches disk until each hunk is decided; the decided text is then written in one WorkspaceEdit and can be undone. A write that reaches the MCP server without a matching review is refused, so a wrong approval policy still cannot write silently.
  • Harness features. Deferred tool loading: five tools are preloaded; run_command, find_symbol and list_files load on demand, visible in the session as list_tools / call_tool. Subagents are enabled for discovery in large repos. Compaction triggers at 60k input tokens.
  • Streaming and cancel. Tokens render as model.message.delta events arrive; the editor never waits on the model. Esc or Stop calls sessions.cancel, kills running commands, discards open reviews and rolls back anything the run wrote, so a cancelled run leaves the workspace as it was.

4. How context is selected

Explicit first, then retrieved, always under a budget: 10,000 tokens for agent mode, 2,500 for inline edits. On startup Anvil indexes the workspace (Flask: 214 files, 1,554 chunks, 985 symbols in about 0.3 s) into function, class, method and doc-section chunks, a symbol table and a Python import graph, refreshed when files change.

  • Mentions. @file: and @sym: (with autocomplete) go in first, whole file or defining chunk.
  • Ranking. BM25 over chunks, plus path matches, exact code identifiers from the request, and analogues: for "add a new X", files that already define several X's (cli.py defines routes_command, shell_command...).
  • Companions. If the request asks for a test or docs, the test file and doc page of the top source file are pulled in.
  • Packing. Breadth first: every selected file gets its single best view before any file gets a second chunk, so a companion is never starved by one large file. Leftover budget buys more chunks, then signature outlines.
Figure 2. What retrieval chose for Task B on Flask 3.1.3, from the actual run. Green rows are the files that had to change.

Trade-off. Lexical and structural retrieval, not embeddings: deterministic, instant, needs no extra model or service, and it can explain every pick. Its weakness is vocabulary mismatch, which the agent covers with search_code and find_symbol.

Figure 3. TrueForge's approval pause becomes the per-hunk review. The approved call is matched to its review by a canonical hash of its arguments, since TrueForge does not pass session or call IDs to MCP servers.

5. Model setup

RoleTrueForge modelWhere it runsUsed for
Primaryanthropic/claude-sonnet-5-5Anthropic API, TrueForge anthropic catalog providerTasks A and B
Fallbackanthropic-compat/claude-haiku-5-5Anthropic's OpenAI-compatible endpoint, a separate custom providerTask C
Developmentmock/mock-coderScripted OpenAI-compatible server on localhostAll automated tests, free

The fallback is a separate provider entry, so invalidating the primary's key (Task C) does not take it down too. Cost. Task A takes about 3 s; Task B about 50 s and about 329k input tokens (mostly cache reads) plus 6.4k output, under $0.75 even at uncached prices. Total spend for development, rehearsals and recording: under $5. Switching models: the ordered anvil.models setting or Anvil: Select Model Order; keys live only in TrueForge. Nothing in the extension is provider-specific, and inline edit uses a tool-free agent with a plain fenced reply, so it works on models with weak tool calling. Resilience: a failed turn that produced nothing is retried with exponential backoff, then re-run on the next model in a fresh session, with no user action. A run that already wrote files is never replayed automatically.

8. Known limitations

Verified on the real model: Task A changes code and docstring in 2 hunks; Task B, run twice, changed cli.py, tests/test_cli.py, docs/cli.rst and CHANGES.rst each time, taking tests/test_cli.py from 58 to 61 and 60 passing; Task C fell back to Haiku in about 5 s with git status clean. Automated: 15 unit tests, a live TrueForge loop test, and 8 tests inside a real VS Code instance. Limits:

  • Retrieval is lexical and structural, so matches that share no words rely on the agent's own searching.
  • Symbols come from regular expressions (Python, JS/TS), not a language server.
  • Once a run has written files, a model failure stops the run instead of switching models mid-way.
  • Whole hunks only: no accepting half of a hunk.

With another month: language-server symbols and references; an embedding re-ranker behind the lexical stage; handing the transcript to the fallback model mid-run; and a TrueForge pull request adding fallback model chains to agent specs.
